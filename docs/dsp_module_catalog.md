# DSP overlay modules of segment g (Cortex-M co-processor): catalog

Generated by `tools/module_catalog_full.py` (probes) and `tools/catalog_report.py` (this file) from `docs/dsp_module_catalog.json`.
All numbers come from running the **real firmware loader and module code in the unicorn Cortex-M4 emulator** (`tools/emu_host.py`), module by module, with all parameters set to 50 unless stated. **Confidence:** `V` = behaviour measured and consistent with an independent fact (CFW manual or data in the module); `I` = inferred (position/order or class only); `?` = unknown.

**What the modules are (important).** Only groups 0, 1, 6, 7 and 8 actually process audio inside the module (`ENTRY2`). In groups 2, 3, 4, 5 and 9 `ENTRY2` is a few dozen instructions: it latches the scaled parameters (`p * 0.01` etc.) and, for the amps, recomputes a block of filter coefficients into an engine data window, while the signal processing runs in the RAM-resident engine in segment c (`0x200009a1`). Their audio behaviour therefore **cannot be measured with the module-level harness** (the full-engine twin still routes silence into the chain, see FINDINGS section 21). For those groups this catalog gives sizes, parameter counts, coefficient-window usage and CPU cost of the module part only.

**CPU cost.** `instr/blk` = emulated instructions of one `ENTRY2` call on a 64-frame stereo block (after warm-up, noise input). One block is 64/44100 s = 1.45 ms = 278,640 cycles at 192 MHz. The CFW manual quotes DSP-meter points for the stock choruses: A-Chorus about 13 points, B-Chorus about 6 points. Modules 1.5 and 1.6 measure 13,587 and 6,777 instructions: 1,045 and 1,130 instructions per point, so about **1,100 instructions per meter point** (used in the "pts" column; the ratio A:B = 2.0 against 2.2 in the manual is an independent confirmation that these two modules are the stock A-Chorus and B-Chorus).

## 6. Group 3 — AMP (slot 3): 22 modules + group 9 (Clone engine)

Each amp module reads 3 to 7 parameters (gain, tone controls, volume ...), scales them (`*0.01`, `*0.009` ...) into the engine window at `0x28001108`-ish and recomputes a six-coefficient filter block (a tone-stack style pole/zero design; checked in module 3.0, whose `p1` goes through polynomials with constants such as 0.494985 and 0.9899). **Names**: only two are inferable. A preset that names an unknown amp falls back to index 0, which the manual calls TWD Deluxe, and the last stock amp is Voks Bass (the manual: the Smart Box amps start after it). 3.21 is the smallest module (1556 B, 3 parameters), a fit for a bass amp. Modules 3.4, 3.17, 3.20 and 3.21 are linked differently from the rest (entry points 0x10003851 / 0x10003e35, no common slot-base pointer): probably amps with another tone-stack or a bass topology (?). 3.18 (12,128 B, ENTRY1 12,108 instructions) and 3.19 (9,908 B, 7,797 instructions) build large tables when selected (waveshaper or cabinet-like tables?).

## 10. Group 8 — RVB (slot 8): 10 modules and the resident library (group 10)

Each module (240-340 B) only fills a parameter struct at `0x100184e4` (mix, a decay/size scale, damping ...) and calls the **resident library** through the two function pointers at `0x10018800` / `0x10018804` (two references per module, verified by the code scan). The reverb algorithm is therefore in group 10 (8,312 B, export A at +0x5fc builds the working structures). Parameter indices differ per module (E2 reads p1 or p2 for the decay), so the table uses all non-mix parameters = 0 / 50 / 100 and an input burst (mix 100); `T30` = time for the envelope to fall 30 dB below its peak (the probe window ends at 2.8 s).

The per-model decay ranges (the manual says up to about 13 s) are not reproduced by a 2.8 s window, so treat the names as order-based guesses. The library part costs about 24.4k instructions per block (about 22 points) for every reverb.

## 11. Cross-checks that support the structure

1. EQ band tables equal the manual: verified for all three EQ models.
2. FX1 15 modules vs FX2 17: FX2 = FX1 without module 14 (AC G) plus three extras (Pitch, Octave, Detune): matches the CFW manual ("FX1 ends with AC G", "FX2: Pitch, Octave, Detune").
3. Delay structure: nine modules, six with 1 s lines, one with 0.5 s, two with doubled time units, delay lines of 44,128 / 22,136 / ~44,150 bytes (int16 at 22.05 kHz): matches the manual's ranges (Slap 300 ms, Reverse and Ping Pong 500 ms, others 1000 ms).
4. A-Chorus : B-Chorus cost = 2.0 (manual 13 : 6 points).
5. Reverb modules are tiny and call the library (10 stock reverbs = 10 modules).

## 12. Not done / limits

- **No behavioural measurement for DRV, AMP, CAB and EQ** because their DSP is in the segment-c engine; the engine twin does not yet route audio through the chain (FINDINGS section 21).
- Amp and drive **names** beyond the two amp indices (0 and 21) are unknown; the manual gives only a few names.
- FX1 modules 1.3 and 1.4 are unidentified. All FX behaviour is for parameters 50 (and 0/100 for the modulation test); parameter meanings were not mapped one by one (the sweep in `docs/module_param_sweep.md` has the sensitivity per parameter).
- The harness passes `args[0x14] = 0`; the real engine passes `60000 / halfword(state+8)` (set by a message from the other chip). Modules that depend on it may behave differently on the pedal.
- Module state sizes were measured by pre-filling RAM (write hooks in this unicorn build corrupt multi-register stores, so they are not used).
